FlowIME P8B.2 - Gameplay Eligibility
====================================

Base: P8B.1.1 diagnostic history fix.

What changed
------------
- Adds conservative Game context classification on top of the validated Fullscreen signal.
- Fullscreen alone is never treated as a game.
- Strong evidence sources:
  1) read-only Windows GameConfigStore exact executable match;
  2) documented Shell Direct3D-exclusive fullscreen state.
- QUNS_BUSY is intentionally not considered game evidence.
- Adds privacy-bounded recentGameplay diagnostics and detailed context signal source/confidence.
- No gameplay input policy is registered yet; IME behavior should remain unchanged.

Validation
----------
1. dotnet test -c Debug
2. dotnet run --project .\src\FlowIME.App\FlowIME.App.csproj -c Debug
3. Chrome F11 should remain Application,Fullscreen (no Game).
4. Launch a real game in fullscreen/borderless fullscreen, then copy diagnostics.
5. Look for Application,Fullscreen,Game and recentGameplay eligible=True.
6. If a real game remains eligible=False, send the recentGameplay lines before enabling any English-lock policy.
