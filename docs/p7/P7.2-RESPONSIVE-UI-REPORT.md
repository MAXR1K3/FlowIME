# FlowIME P7.2 — responsive UI hardening

P7.2 is a presentation-layer hardening pass based on P7.1. It does not alter the automation engine, rule resolution, input-method providers, persistence, foreground monitoring, tray lifecycle, or diagnostic services.

## Design model

The layout now treats available window space as a constraint instead of assuming a single desktop width. The primary rule is: **reflow before compression**.

- Text blocks that can contain user/application data wrap rather than using character ellipsis.
- Text + switch / text + button rows move controls underneath the description when the window is narrow.
- Multi-card areas change column count at width breakpoints.
- Page padding becomes smaller as available width decreases.
- Primary pages keep horizontal scrolling disabled; overflow is resolved through reflow.
- Dialog content has compact/wide states and the Add Application dialog also adapts to low-height windows.

## Breakpoints

Breakpoints are expressed in effective pixels through WinUI `AdaptiveTrigger` states.

- Compact: baseline state from 0 effective pixels.
- Comfortable: generally from 720–760 effective pixels depending on the page.
- Wide: generally from 1100 effective pixels.
- Rule cards use a dedicated 860 effective-pixel breakpoint because their local action density is higher.

These values intentionally describe layout behavior rather than physical display pixels, so Windows DPI scaling continues to participate in the layout system.

## Page changes

### Shell
- TitleBar uses `MinHeight` instead of a fixed height.
- The decorative subtitle is hidden on narrow windows.
- NavigationView keeps its existing automatic expanded/compact/minimal behavior.

### Home
- Automation switch moves below its description in compact mode.
- Live status uses 1 / 2 / 3-column arrangements for compact / medium / wide windows.
- The “set current app” action drops below rule details on narrow windows.
- Application/process/profile labels wrap instead of being trimmed.

### Rules
- Page header action, global-default action, and search count all reflow vertically on compact windows.
- Each rule card has compact and wide visual states.
- In compact mode, enable toggle, target badge, and edit/delete actions are stacked underneath the app identity.
- Executable paths and target labels wrap.
- Empty states use smaller safe padding.

### Settings
- Each switch/button can move beneath its description.
- Long setting descriptions remain readable under large text scaling and narrow windows.

### Input Method Support / About
- Responsive page padding is shared with the rest of the shell.
- About identity moves below the icon on narrow windows.

### Dialogs
- Add Application: 340px compact content / 600px wide content; input method and input state controls stack in compact mode.
- Add Application additionally lowers the running-app list height on short windows.
- Edit Rule and Global Default: 340px compact / 520px wide content; toggles move underneath explanatory text on compact windows.
- User/application text wraps rather than using character ellipsis.
