# R3.4 高级规则匹配与冲突诊断报告

## 状态

R3.4 已实现并完成自动化测试与 Windows 实机界面验证。

本阶段不包含 Microsoft Store/AppX 非运行应用发现；该阶段按用户要求继续跳过。

## 已实现能力

### 1. 高级匹配条件

添加与编辑规则均提供折叠的“高级匹配”区域：

- 进程名：不区分大小写的精确匹配；
- 窗口类：不区分大小写的精确匹配；
- 窗口标题：不区分大小写的包含匹配；
- 优先级：`0–10000`。

进程名、窗口类和窗口标题等高级条件采用 AND 语义。未填写字段不构成限制。应用身份继续采用既有的稳定身份优先策略（AUMID → PFN + EXE 名 → 路径/进程名回退），以避免 packaged app 更新后的版本化路径使旧规则失效。

### 2. 匹配预览

编辑器实时显示规则条件，例如：

```text
可执行文件 = C:\Apps\Chrome.exe 且 进程名 = chrome 且 标题包含 Docs
```

输入值在保存前会去除首尾空白；空白字符串规范化为未设置。

### 3. 同一 EXE 的多场景规则

同一 EXE 可以保存多条高级条件不同的规则，例如：

- Chrome 通用规则；
- Chrome 且标题包含 `Docs`；
- Chrome 且窗口类为某个值。

只有应用身份及三个高级字段均等价时才执行更新，而不创建重复项。现有 packaged-app 规则仍保留 PFN/AUMID 跨版本路径更新行为。

### 4. 规则关系与冲突诊断

核心分析器与实际 RuleEngine 的选择顺序一致：

1. 优先级降序；
2. 条件具体程度降序；
3. 规则 ID 升序，保证稳定结果。

当前诊断识别：

- 完全相同的匹配条件；
- 相同条件但不同目标的冲突；
- 相同条件和目标的冗余；
- 高优先级宽规则覆盖低优先级窄规则；
- 同优先级且可以同时匹配的规则；
- 候选规则可能覆盖现有规则或被现有规则覆盖。

添加/编辑对话框会实时显示候选关系提示；规则页健康检查会显示规则集级别摘要。诊断只报告，不自动改写用户规则。

### 5. “为什么这样切换”

首页的决策说明现在显示实际命中条件和规则优先级，包括：

- 当前 EXE；
- 进程名；
- 窗口类；
- 标题条件；
- PFN/AUMID（存在时）；
- 命中规则优先级。

未命中应用规则时，会明确说明使用全局默认、场景策略或不干预。

## 兼容性

- `ApplicationMatch` JSON 字段未更名；旧规则可直接读取。
- 仓储会将旧 JSON 中的空白可选字段规范化为 `null`；RuleEngine 也会防御性忽略空白条件。
- 无 EXE 路径、仅按进程名/窗口类/标题匹配的既有规则不再从规则列表中静默消失。
- 全局默认仍只支持 Chinese/English。
- 应用规则仍支持 Keep/Chinese/English。
- PID 不进入持久化规则身份。
- 未加入 AppsFolder、Start Menu 或非运行 AppX 发现。

## 独立审查

独立审查发现并已修复：

- 首页“编辑此应用规则”曾只恢复动作和 Provider，可能把高级规则保存成额外宽规则；
- 无路径的有效规则曾在 UI 投影中被静默隐藏；
- 旧 JSON 空白高级字段与分析器的 `null` 语义不一致；
- 相同 AUMID、不同历史路径/EXE 名时，分析器曾与引擎的稳定身份优先语义不一致。

审查中关于“标题包含 `Docs` 与 `Settings` 必然互斥”的意见未采纳：包含条件可以同时成立（例如标题同时包含两者），因此保留保守的潜在竞争提示。关于 AUMID/PFN/路径必须全部 AND 的意见也未采纳，因为这会破坏既有 packaged app 跨版本路径兼容；稳定身份仍是一个分层身份约束，高级窗口条件再与该身份约束做 AND。

## Windows 实机验证

已验证：

- 应用可启动；
- 添加规则对话框可展开“高级匹配”；
- 编辑现有规则可展开“高级匹配”；
- 双列紧凑布局可同时显示进程名、窗口类、标题、优先级和匹配预览；
- 首页“为什么这样切换”实际显示 EXE、PFN/AUMID 与优先级；
- 最近自动化日志未匹配到 `Unhandled`、`XamlParseException`、`InvalidOperationException`、`ArgumentException` 或 `stage=exception`。

为了不修改用户现有 Chrome/Codex 规则，实机检查中没有点击“保存/更新规则”。高级条件的保存、读取和冲突判定由自动化测试覆盖；仍建议用户执行一次真实规则验收。

## 人工验收建议

1. 为同一浏览器保留通用规则；
2. 再创建标题包含某个稳定文本的高级规则；
3. 让高级规则优先级高于通用规则；
4. 打开匹配标题和不匹配标题的两个窗口；
5. 检查输入状态分别按高级规则和通用规则切换；
6. 展开首页“为什么这样切换”，确认显示实际命中条件和优先级；
7. 将宽规则优先级调得更高，确认界面出现覆盖警告；
8. 重启 FlowIME，确认高级条件和优先级仍然存在。
