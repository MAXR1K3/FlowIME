# R3.3.2 Application Target Selection Report

## Scope

R3.3.2 expands application-rule creation beyond visible, currently running windows.

The add-rule dialog now supports:

- visible applications;
- accessible background processes without a visible top-level window;
- search by display name, process name, executable filename, or full path;
- manual selection of an existing `.exe`, including software that is not running;
- custom rule display names;
- source labels: `正在运行`, `后台进程`, `手动选择`;
- existing provider and `保持（不切换）/中文/英文` selection.

A non-running program is represented by its executable path, not by a synthetic process identity. Process IDs and window handles are never persisted as rule identity.

## Implementation

### Candidate discovery

`RunningApplicationCatalog` now merges:

1. resolvable visible top-level applications, preserving HWND and package identity;
2. accessible processes with resolvable executable paths.

Candidates are deduplicated case-insensitively by normalized full executable path. Visible-window candidates take precedence so package family name and AUMID are retained when available. The FlowIME process and inaccessible/unresolvable processes are excluded.

### Search and customization

`AddApplicationViewModel` maintains the complete candidate set and a filtered projection. Search covers:

- display name;
- process name;
- executable filename;
- full executable path.

A selected candidate initializes the editable rule name. Blank or whitespace-only names fall back to the resolved application display name.

### Manual executable selection

The WinUI `FileOpenPicker` is initialized with the FlowIME main-window HWND and restricted to `.exe` files. `ExecutableCandidateFactory`:

- requires an existing `.exe`;
- normalizes the full path;
- reads FileDescription/ProductName when available;
- falls back to the filename without extension;
- creates a non-running candidate with PID/HWND equal to zero.

The existing shell thumbnail loader supplies the icon. If Windows exposes no specific icon, the generic fallback remains visible; FlowIME does not invent or misattribute branding.

## Evidence boundaries / remaining manual acceptance

The native picker was opened and cancellation was verified. This automated run did not complete a real file selection and did not persist a new manual rule, because doing so would alter the user's rule configuration. The user should complete the following acceptance steps with a disposable executable or desired target:

1. Browse to a non-running `.exe`.
2. Confirm display name, icon, source label, and full path.
3. Change the custom rule name.
4. Select provider and input state.
5. Save and restart FlowIME.
6. Launch/focus the target and verify the rule applies.
7. Select the same executable again and confirm the update-existing flow rather than duplication.

Non-running Microsoft Store/AppX discovery is not part of R3.3.2. The user has explicitly deferred/skipped that stage. Existing packaged applications discovered while running retain PFN/AUMID support, but FlowIME will not add an AppsFolder/Start Menu catalog unless the requirement is reactivated.
