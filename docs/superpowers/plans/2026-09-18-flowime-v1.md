# FlowIME V1 Implementation Plan

**Goal:** Ship a Windows 11 x64 utility that applies per-application Microsoft Pinyin `Keep / Chinese / English` rules.

**Architecture:** Core logic is platform-independent. Windows-specific code owns WinEvent, process identity, IMM32 and TSF. The P0 Probe is completed before a production input backend or WinUI shell is accepted.

**Tech stack:** C# / .NET 10, WinUI 3 later, Windows App SDK, Win32/IMM32/TSF interop, xUnit v3.

**Spec:** `docs/superpowers/specs/2026-09-18-flowime-v1-design.md`

## P0 execution tasks

1. Bootstrap solution/projects/tests and central package versions.
2. Implement Core domain types and deterministic RuleEngine tests.
3. Implement `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` on a dedicated native message-loop thread.
4. Implement WindowResolver for HWND → PID/TID/process path/title/class/package family when available.
5. Implement `FlowIME.Probe` commands: `watch`, `inspect`, `set`.
6. Implement the experimental cross-process IMM path using `ImmGetDefaultIMEWnd` + `SendMessageTimeout(WM_IME_CONTROL, IMC_GET/SETOPENSTATUS)` and keyboard-layout inspection.
7. Implement TSF active-profile inspection and local thread-manager compartment inspection. Produce a P0 report before proceeding.

## P0 acceptance matrix

For Notepad, Explorer, Chrome, Edge, VS Code, Windows Terminal and WeChat on Windows 11 with Microsoft Pinyin:

- inspect while Chinese
- inspect while English
- set Chinese and re-inspect
- set English and re-inspect
- confirm no inserted characters, menus, shortcut side effects or focus theft
- record behavior for elevated targets

Only after this matrix is run do Tasks 8+ begin: production backend, automation coordinator, persistence, WinUI shell, rule picker, tray/startup, diagnostics, indicator, packaging and release testing.
