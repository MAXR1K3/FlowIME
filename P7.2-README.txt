FlowIME P7.2 Responsive UI

Base: P7.1

Goals
- Use responsive layout states instead of desktop-only fixed composition.
- Prefer reflow, wrapping and vertical stacking over squeezing text or controls.
- Keep horizontal scrolling disabled on primary pages.
- Preserve the P7.1 warm beige light theme and Windows-native dark theme.
- Do not change input switching, provider, rule-resolution, persistence, foreground watcher or tray logic.

Responsive behavior
- Compact (< ~720 effective px): reduced page padding, actions move below text, status cards stack vertically.
- Medium (~720-1099 effective px): balanced padding, status cards use two-column layouts where useful.
- Wide (>= ~1100 effective px): original desktop density, including three-column status presentation.
- Rule cards switch from side-by-side controls to a vertical action flow on narrow windows.
- Add/Edit/Global dialogs have compact and wide states.
- Add Application dialog also adapts to short window heights.
- Long app names, process names and executable paths wrap instead of being character-trimmed.
- Nonessential title-bar subtitle is hidden on narrow windows.

Validation
- All XAML files parse as XML.
- All VisualState Setter targets resolve to named elements in their XAML namescope.
- All declared UI event handlers resolve to existing code-behind methods.
- FlowIME.Core, FlowIME.Windows, FlowIME.Infrastructure, FlowIME.Probe and FlowIME.App/Services are unchanged from P7.1.

Run
  dotnet test .\tests\FlowIME.App.Tests\FlowIME.App.Tests.csproj -c Debug
  dotnet run --project .\src\FlowIME.App\FlowIME.App.csproj -c Debug

Recommended manual smoke test
1. Start at 1120x760, 100% scaling.
2. Resize progressively to ~900, ~720 and ~520 effective px width.
3. Check Home, Rules, Input Method Support, Settings and About.
4. Open Add Application, Edit Rule and Global Default dialogs while narrow.
5. Repeat at Windows display scaling 125%, 150% and 200% if available.
6. Verify no horizontal scrollbar, clipped buttons, overlapping text or unusable toggles.
